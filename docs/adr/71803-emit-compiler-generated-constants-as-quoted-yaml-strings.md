# ADR-71803: Emit Compiler-Generated Constants as Quoted YAML Strings, Not Literal-Only Expressions

**Date**: 2026-10-25
**Status**: Proposed
**Deciders**: Not yet recorded; approval remains pending PR review.

---

### Context

The gh-aw compiler binds extracted GitHub Actions expressions to environment variables using `${{ <content> }}`. For a few compiler-generated values the "expression" was really a constant: deferred prompt markers were wrapped as `${{ '__GH_AW_DEFERRED_…__' }}`, and the unconditional pre-activation output was emitted as `activated: ${{ 'true' }}`. The workflow linter's obfuscation rule flags these literal-only expressions, although workflow authors cannot repair bindings generated by the compiler. Generated constants must avoid unnecessary expression evaluation without changing authored expression handling or weakening the lint rule. Environment values and job outputs must also stay string-typed; a bare YAML `true` would become a boolean.

### Decision

The compiler will mark generated constants explicitly with an `IsLiteral` flag on `ExpressionMapping`, avoiding linter exemptions or content-based inference. Deferred prompt rewriting sets this flag and stores the bare marker; `ExpressionMapping.environmentValue()` emits flagged values as Go-quoted (`%q`) YAML strings for prompt creation and interpolation/template rendering, while placeholder substitution writes them through `writeYAMLEnv`. When the pre-activation `activated` output is a `StringLiteralNode`, the compiler also emits its value as a quoted string (`"true"` for the unconditional case). Unflagged mappings retain their existing handling, including the placeholder emitter's legacy quoted-value detection; late job output/result bindings in the agent job and the obfuscation rule remain unchanged.

### Alternatives Considered

#### Alternative 1: Suppress or exempt compiler-generated bindings in the obfuscation linter

Add an allowlist or exemption to the linter for known generated patterns (for example, `__GH_AW_DEFERRED_*` markers and `activated: ${{ 'true' }}`). This would leave code generation untouched. It was rejected because it weakens a security-relevant lint rule, couples the linter to compiler internals, and keeps emitting expressions that do nothing.

#### Alternative 2: Infer literalness from expression content at emit time

Extend quoted-value detection to prompt creation and interpolation/template rendering, automatically unwrapping content such as `'...'` without a new field. This would reuse the placeholder emitter's existing heuristic, but could reclassify authored expressions such as `'authored literal'` or misidentify `'first' || 'second'`. An explicit flag set only by the compiler limits the new behavior to generated values without broadening that legacy heuristic.

#### Alternative 3: Emit unquoted YAML scalars

Write the constant directly (for example, `activated: true`). This was rejected because YAML would parse `true` as a boolean and change the type of job outputs and env values, which must remain strings.

### Consequences

#### Positive
- Deferred prompt markers and the unconditional pre-activation output no longer produce literal-only obfuscation findings; other findings remain subject to the existing rule.
- The lint rule keeps its full strength because nothing is exempted.
- A shared `environmentValue()` helper makes prompt creation and template interpolation emit literal bindings the same way. Placeholder substitution emits the same quoted value through `writeYAMLEnv`.
- Quoted emission keeps values string-typed, and the tests check this by round-tripping through a YAML parser.

#### Negative
- `ExpressionMapping` now carries two value semantics (expression or literal), so every new emission site has to handle `IsLiteral` or call `environmentValue()`. Otherwise it reintroduces the problem or produces a wrong binding.
- Generated lock files change textually (`${{ '__GH_AW_DEFERRED_…__' }}` → `"__GH_AW_DEFERRED_…__"`, `${{ 'true' }}` → `"true"`), which causes churn on recompilation. Tests and tools that match on the old text must be updated.
- Go `%q` quoting is used as YAML double-quoted quoting. This works for the tested inputs (quotes, newlines, backslashes), but it depends on the two escaping grammars staying compatible for compiler-generated content.

#### Neutral
- Late job output/result bindings in the agent job's "Resolve deferred prompt expressions" step remain `${{ … }}` expressions, so prompt rendering and substitution semantics are preserved.
- Pre-activation conditions with real checks still emit `${{ … && … }}` expressions. Only the case that reduces to a pure literal changes.
