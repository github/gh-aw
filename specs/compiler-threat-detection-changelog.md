# GitHub Actions Compiler Threat Detection Changelog

**Specification**: https://github.com/github/gh-aw/blob/main/specs/compiler-threat-detection-spec.md
**Editors**: GitHub Next (GitHub, Inc.)

This changelog records the version history and the dated mapping audits for `specs/compiler-threat-detection-spec.md`. The specification itself holds only normative requirements; every version bump and every daily optimizer audit entry is recorded here.

## Version History

The 1.0.90 transport contract additionally requires fail-closed rejection of gateway `${NAME}` references after runtime-data substitution, including boundary-assembled references and mixed authored/runtime strings. The pinned gateway expands raw JSON and parsed header/environment values again; launcher-local single-pass replacement does not prevent that downstream credential-expansion path. Regression evidence covers dummy-credential payloads and both downstream expansion stages without live endpoint calls.

Review corrections for 1.0.90 require proven Bash-decoded quoted delimiters, mount expression transport across all JSON engine renderers, and canonical binding values for whitespace-equivalent expressions. Legacy-reference and mixed-value compatibility MUST NOT weaken the downstream expansion check.

Compatibility diagnostics for 1.0.90 reject statically visible mixed gateway/transport values before lock emission and warn, without configuration values, when shell computations will remain literal. The source codemod shares the compiler's Bash boundaries, preserves quoted bodies and comments, and fails atomically on unproven heredocs. These migration aids do not replace runtime rejection of dynamic placeholder data or make gateway variables available on the runner.

Further 1.0.90 review regressions cover scalar/array expression transport, built-in GitHub volume bindings, data-only mount allowlist exports, normalized former heredoc escapes, unsupported CA-path rejection, and suffix-preserving Bash references in the compiler and source codemod. These corrections retain the same runtime guard and compatibility version.

The unreleased 1.0.81 merge-policy mapping also covers ambiguous check producers, compiler rejection of explicit/default/suffixed agent-controlled check names, validated submission-time review ordering, and same-count approval replacement during revalidation. It distinguishes runtime-required `checks: read` from the absence of check-run reads or returned metadata when requirements are empty, in both live and staged mode. Evidence mappings include structural-only debug records, count-only label/pattern logs, and status/phase error logs with full diagnostics retained in untrusted results. Approval provenance remains available for audit and final revalidation; neither metadata designation nor check-name matching authenticates an instruction source or expected check producer, and log minimization does not establish prompt-injection isolation.

### Mapping Audit (2026-10-27)

#### Immutable PR Revision Isolation

Reviewed immutable PR checkout in [PR #72541](https://github.com/github/gh-aw/pull/72541), `actions/setup/js/checkout_pr_branch.cjs`, event evidence propagation in `aw_context.cjs`, their regression suites, and the `TestFormalRS05a_*` runtime bridge cases. Checkout fetches a validated immutable SHA from the current repository's origin and verifies actual `HEAD` before success or baseline export. Ordinary PR events retain their recorded revision across head movement or branch deletion; labels and reviews reject stale revision evidence, with reviews bound to `commit_id`. API-resolved paths recheck the head after fetch. Malformed PR dispatch context and unavailable required evidence fail explicitly.

Issue comments and unbound manual dispatch remain current-head execution, not historical revision approval. Comment timestamps surface newer PR activity without claiming that timestamps prove approval or rejecting the router's own status-comment update. Actor permission and same-repository bot restrictions remain independent. Tests cover invalid/missing context, API failure, stale event/review evidence, API/fetch races, mismatched actual commits, and real Git checkout after branch deletion and head movement. The bounded SMT model covers authorization only; solver execution was unavailable during this change's validation. No live dispatch or exploit testing was performed.

This maps a runtime control, not a compiler-detectable threat or a new `CTR-*` rule. CTR-008/028/030, generated lock-file schema, and permission grants remain unchanged. The earlier retained-ref audit below describes the superseded implementation, not the current revision-selection contract.

Compilation remains offline; existing action-pin metadata does not establish a complete vulnerable-version inventory. Arbitrary shell dataflow, action internals, and cross-job provenance remain unproven, and no live attack or workflow dispatch is claimed.
